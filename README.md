## 起動

検証環境：Flutter 3.44.8 / Dart 3.12.2 / Xcode、iOS 15以降。

```sh
cd /path/to/ekidoko
flutter pub get
open -a Simulator
flutter devices
flutter run -d <デバイスID>
```

初回はSwift Package ManagerがMapLibre Nativeを取得します。クイズ中の実地図にはインターネット接続が必要です。ホームの固定プレビューは通信せずに表示します。APIキー・登録・有料契約は不要です。

ホームの東京駅プレビューは、同梱した`tokyo_home_map.png`を表示する固定画像で、外部タイルを読み込みません。クイズ中の実地図は引き続きMapLibreのタイルを使用します。

## ゲーム

- ホーム → クイズ → 正誤表示 → ランク発表 → 詳細結果。回答は**4択**です。10問終了後はランク発表カードを表示し、カードをタップすると合計点と駅別結果へ進みます。
- ホームで**Easy / Hard**を選択して開始します。初期選択はEasy。クイズ上部と結果に難易度を表示し、ゲーム中の変更は禁止します。
- Easyは`enabled && easyEligible`、Hardは`enabled`の駅からランダムに10駅を選び、同じゲームで重複させません。100駅以上に増えても1ゲーム10問です。
- Easyは全国のEasy対象駅から不正解候補3駅をランダムに選択。Hardは新幹線が通る駅を正解とする場合、新幹線の線路が確認済みの駅だけを選択肢にし、その中で同じ都道府県 → 同じ地方 → 隣接地方 → 全国の優先順で選びます。その他のHard問題は同じ地域優先です。両モードとも正解1駅を加えて表示順をランダムにし、ヒントを使っても選択肢は変わりません。
- 回答確定後の変更は禁止。正解は赤、残念は青のタイルで表示します。
- 正解時は100 / 70 / 40 / 10点、不正解は0点。結果では合計・正解数・ノーヒント正解数・各問題を表示します。合計点は変えず、Easy `×1.00`・Hard `×1.10`のランクポイントで共通評価します。ランクはSS（1,050以上）/ S（850–1,049）/ A（700–849）/ B（500–699）/ C（300–499）/ D（0–299）です。そのためEasy満点はS・1,000ランクポイント、Hard満点はSS・1,100ランクポイントになります。トップ画面には端末内に保存した過去最高ランクを表示します。ランクポイントの「？」から換算式と基準を確認できます。得点や駅ごとの回答履歴は保存しません。
- 再プレイでは同じ難易度を維持し、回答・得点・ヒント・選択状態をリセットします。ホームに戻ると難易度を再選択できます。
- ホームのタイトルは「Ekidoko」、正方形の紹介地図は東京駅周辺の地図と線路を含む固定画像です。ホームでは地図タイル通信を行いません。広告・課金・登録はありません。

### Easy / Hardの違い

Easyは全国的に知られた主要34駅から出題・不正解候補を選びます。Hardは有効な全50駅から出題し、近い地域の不正解候補を優先します。正解駅に新幹線の実線路geometryが確認されている場合は、誤答候補も新幹線の線路が確認済みの駅に限定します。この判定は`stations.json`の`hasHighSpeedRailway`で明示し、地図ヒントデータのgeometryとテストで一致を検証します。10問、地図、3段階ヒント、100 / 70 / 40 / 10点の採点は共通です。Easy対象は`easyEligible`で明示し、未計測の数値項目`difficulty`とは独立して管理します。初期10駅はすべてEasy対象。34駅の分類は初期判断であり知名度を客観的に測定した結果ではありません。選択状態はアプリ実行中のみ保持します。

Easyは正解以外の有効なEasy対象駅すべてからランダムに3駅を選ぶため、全国の遠い駅も同じ地域の駅も登場します。Hardは以下の共通処理で近い地域を優先します。両方とも同名駅の重複を防ぎ、表示順をシャッフルします。

### Hardの地域別4択生成

不正解候補は、今回の10問だけでなく、現在利用可能な有効駅の全体から選びます。各段階では既に選んだ駅を除き、不足分だけランダムに補います。3駅そろったら下位の地域には進みません。IDに加えて駅名も重複を除外し、空白や末尾の「駅」の表記違いも同名として扱います。無効駅は選択肢に含めません。

共通設定は`lib/game/station_choices.dart`です。元の駅データを変更せず、「関西」は「近畿」、「中部・北陸」「北陸」「東海」は「中部」、「九州・沖縄」は「九州」として候補を分類します。隣接地方は海を挟む近隣も含むゲーム用の設定で、次の双方向の関係を使用します。

| 地方 | 隣接地方 |
|---|---|
| 北海道 | 東北 |
| 東北 | 北海道・関東・中部 |
| 関東 | 東北・中部 |
| 中部 | 東北・関東・近畿 |
| 近畿 | 中部・中国・四国 |
| 中国 | 近畿・四国・九州 |
| 四国 | 近畿・中国・九州 |
| 九州 | 中国・四国 |

例えば東京は東京都の他の8駅から3駅、新大阪は大阪・天王寺・京橋・難波から3駅、名古屋は金山・千種と中部の1駅になります。札幌は函館・旭川と東北の1駅、博多は小倉・久留米と九州の1駅になります。いずれも最後に4択をシャッフルします。

未定義の地方でも、同じ都道府県・同じ地方を優先した後、全国から補完して停止を防ぎます。ただし有効な駅名が4種類未満なら、重複した選択肢を作らず、起動時の既存のエラー画面に原因と再読み込みを表示します。1ゲーム10問のため、有効な駅の総数は引き続き10駅以上必要です。

50・100駅へ追加する際は都道府県・地方の表記を統一し、地方を増やす場合だけ共通の別名・隣接設定を確認してください。駅ごとの処理は不要です。同名駅は同じ問題の選択肢に並びません。優先順位は地方単位で、実際の距離順や難易度順に並べるものではありません。

## 地図

MapLibre GLとOpenFreeMapのOSM由来ベクトルタイルを使用します。デモタイル・架空の線路は使用しません。50駅すべて同じWidgetと共通スタイル生成処理で描画し、PoCの追加データだけを駅IDで切り替えます。

| 段階 | 短辺方向の表示幅の目安 | 開示する文字 | 点数 |
|---|---|---|---:|
| 初期 | 500m | なし | 100 |
| ヒント1 | 1km | なし | 70 |
| ヒント2 | 3km | 実線路に沿う路線名 | 40 |
| ヒント3 | 5km | 路線名・施設名・地名 | 10 |

線路・道路・建物・河川・公園は実タイルから描画します。補助ヒントもOSMの実線路・名称・位置です。駅名を示す地図マーカーは回答後にだけ表示します。北向き・傾斜0・中心座標を固定し、全ネイティブジェスチャーを無効化、Flutterでも地図タッチを遮断します。ヒントは650msのズームアウトです。

貨物線の名前と貨物専用・側線・操車場の補助ヒントは除外します。名前のない線路には路線名を推測して付けません。従来の補助路線色は識別用で、公式カラーではありません。PoC3駅の追加色は確認済みOSM route relationの`colour`値を使い、事業者資料で路線と色相を照合しています。事業者のブランド仕様RGBと同一であるとは断定しません。

駅そのものの名前・読み・別名、駅前施設などの直接的な答えは除外します。一方「名古屋城」「京都タワー」など市名を含む実在ランドマークは、JSONの`allowedLabels`で名称を明示して残します。通常は駅名を含む名称を除外し、必要なものだけ例外として許可します。「駅」「ステーション」などの直接的な駅参照は例外設定より優先して除外します。駅名が含まれる路線名は従来どおり保守的に除外します。個別に漏出する名称は駅データの`blockedLabels`へ登録できます。

施設と地名は各18件まで選び、重要な実ランドマークを優先します。小さな観光チェックポイントなどは除外し、線路を覆わない密度にしています。

タイルのLODにより広域では建物が省略されます。駅の全ホーム・出口・地下階や工事の最新状態は保証しません。地下線が含まれる場合も実データの線形だけを使います。

## 駅データを1駅追加する

ゲームや画面のDartコードを編集する必要はありません。駅データの正本は **`assets/data/stations.json`** です。各駅には次の項目を登録します。

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | ○ | 重複しない英小文字・数字・`_`・`-`のID |
| `name` | ○ | 駅名（末尾の「駅」を付けない） |
| `nameKana` | ○ | 駅名の読み（ひらがな） |
| `latitude`, `longitude` | ○ | 実駅のWGS84座標。数値で登録 |
| `prefecture`, `region` | ○ | 都道府県・地方区分 |
| `difficulty` | ○ | 1以上の整数 |
| `enabled` | ○ | `true`で利用、`false`で両モードの出題と選択肢から除外 |
| `easyEligible` | ○ | `true`でEasyにも登場、`false`でHardのみ。出題と不正解候補の両方に適用 |
| `osmNodeId` | 任意 | 座標出典のOSMノードID |
| `routes` | 任意 | 路線の情報。配列。これだけで線路上の注釈を生成することはありません |
| `answerAliases` | 任意 | ローマ字・別表記の配列。答えの漏出防止にも使用 |
| `blockedLabels` | 任意 | 個別に隠す名称または部分文字列の配列 |
| `allowedLabels` | 任意 | 市名を含む安全な実ランドマークを許可する名称配列。未収録の地物を生成する機能ではありません |

例えば未登録の駅を追加する場合（以下の`<id>`等は実データで置き換えます）：

1. OSMの`railway=station`ノードなどで追加する駅の実座標・名前・出典を確認します。架空の座標は登録しないでください。
2. JSON配列末尾に1件追加し、重複しない`id`、正式な`name`、ひらがなの`nameKana`、確認した`latitude`・`longitude`、`prefecture`、`region`、`difficulty: 1`（仮設定）、`enabled: true`、`easyEligible: true`または`false`を指定します。既存の1件を見本にし、必要に応じて`osmNodeId`と`answerAliases`を追加します。前の要素とのカンマを忘れないでください。
3. `flutter run`で再起動します。JSONの追加だけで出題候補に入り、同じWidgetで座標を中心に実地図を表示します。デバッグ版では補助データが未同梱なら共通のOSM読取処理で取得します。取得不能なら再試行UIになり、架空のヒントを出しません。
4. 公開用・実機リリース用には、次の共通ツールで補助データを同梱します。駅別のコードやヒント処理は不要です。

```sh
python3 tool/prepare_station_maps.py --fetch --station your_station_id
flutter analyze
flutter test
flutter build ios --simulator
```

ツールはカタログの座標から線路8km以内・施設/地名4km以内を抽出し、`assets/maps/station_hints.json`を更新します。線路をつなぐ際は実座標の端点が一致する場合だけです。APIに存在しない情報は生成しません。生データは`/tmp/ekidoko-osm-hints`にキャッシュし、通信は順次実行します。HTTPエラー時には30秒間隔で再試行します。`--station`を複数回指定すれば新駅をまとめて追加でき、既存駅の補助データと出典を保持します。地域別のOverpass JSONスナップショットから一括生成することもできます。

```sh
python3 tool/prepare_station_maps.py tokyo.json nagoya.json osaka.json kyoto.json
# 複数駅をまとめて更新する例（札幌と仙台は登録済み）
python3 tool/prepare_station_maps.py --fetch --station sapporo --station sendai
# 読取用Overpassの供給元を指定する場合
python3 tool/prepare_station_maps.py --fetch --station your_station_id \
  --endpoint https://overpass-api.de/api/interpreter
```

リリース版は未同梱データのOverpass自動取得を無効にしています。公開APIの混雑・利用方針に配慮し、100駅のヒントは事前生成して配布してください。デバッグ時の取得は検証用で、永続的なオフラインキャッシュはありません。

起動時にID重複・駅名空欄・必須項目欠落・型・座標範囲・同一OSMノード・同名/同読みの近接駅・同一位置の重複を検証します。不備があれば`stations.json N件目 [id]`と原因を画面に表示し、再読み込みできます。Easy対象の有効駅・Hard対象の有効駅は、それぞれ10駅以上必要です。地域・都道府県・駅データ上の難易度の抽出は`StationCatalog.select(...)`で行えます。駅を絞り込む選択画面は未実装です。

## 読み込みとエラー

地図が描画されるまで回答とヒントを無効にします。通信不能・スタイル不良・タイムアウトでは再試行を表示します。再試行で得点やヒント段階は変わりません。実地図を模式地図へ置き換えるフォールバックはありません。

TileJSONの通信タイムアウトは8秒、描画待ちは25秒です。native idleに加え、道路・線路、近景の建物、開示段階のラベルが実際に描画されたことを確認します。SDKが個々のタイル失敗を公開しないため、一部欠落の完全検出は未実装です。模式地図はネット不要のWidgetテストにのみ利用しています。

## 供給元・費用・ライセンス

- `maplibre_gl ^0.27.1` / iOS MapLibre Native 6.28.0：既存の地図SDK。
- `url_launcher ^6.3.3`：出典リンク。テストはFlutter SDKの`integration_test`。新しい依存パッケージは追加していません。

- 補助データはOSMの公開読取APIから開発時に取得。全50駅はローカル同梱のため、プレイ中のOverpassへのアクセスはありません。公開サーバーは混雑・制限があり、商用アプリの継続的な読取用途には自前環境等が必要です。[Overpass利用案内](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)。
- OSMデータはODbL、OpenMapTilesスキーマはCC BY 4.0、Noto SansはOFL。ソフトウェアのライセンスとは別です。地図上に出典を常時表示し、リンクからライセンスを開けます。[OSMの条件](https://www.openstreetmap.org/copyright)。
- 駅座標・補助GeoJSONのデータ部分もODbLで提供します。公開時はデータの取得方法・配布URLを整え、必要な表示を確認してください。`assets/maps/README.md`に記載しています。

有料登録・契約・キー発行は行っていません。大量の地図先読み・オフラインタイル収集、位置情報取得、バックエンドはありません。

## iPhone実機

1. iPhoneを接続し、Macを信頼します。
2. 「設定 → プライバシーとセキュリティ → デベロッパモード」を有効にします。
3. `open ios/Runner.xcworkspace`でXcodeを開き、RunnerのSigning & CapabilitiesでAutomatically manage signingとApple IDのTeamを設定します。
4. 接続したiPhoneを選び一度Runして、署名・ペアリングを確認します。
5. `flutter devices`で端末IDを確認し、以下を実行します。

```sh
flutter run --release --no-resident -d <iPhoneのID>
```

実機で50駅の初期・ヒント、文字の漏出、ジェスチャー禁止、低速通信・機内モード・再試行、画面復帰、4択・回答確定、触覚、出典リンクを確認してください。
