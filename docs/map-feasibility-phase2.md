# Phase 2：全国20駅・実地図品質検証

更新日：2026-10-12。全国20駅からランダムに10問を出題する4択ゲームへ拡張しました。新駅は札幌・仙台・大宮・金沢・静岡・新大阪・三ノ宮・広島・高松・博多です。既存10駅のカタログと補助地物を維持し、ゲーム・UI・採点・650msアニメーションは変更していません。

この文書では「自動描画確認」「スクリーンショットの観察」「人によるゲーム性の検証」を区別します。描画の成功だけで可読性・楽しさ・難易度の均等を保証しません。

## 採用構成

- Flutter `maplibre_gl` 0.27.1、iOS MapLibre Native 6.28.0（SPM）。既存パッケージを継続し、依存パッケージは追加していません。
- OpenFreeMapのOSM由来ベクトルタイル。TileJSONは`https://tiles.openfreemap.org/planet`。版別URLを固定せずTileJSONから解決します。
- 全駅共通のクイズ専用Dartスタイル。道路・鉄道・建物・水域・公園だけを基本表示します。既成スタイル、スプライト、観光アイコン、MapLibreデモタイルは使用しません。
- 日本語glyphはOpenFreeMapのNoto Sans。出典の外部リンクには既存の`url_launcher`を利用します。
- 路線名・実線路・施設/地名をOSMの読取用Overpass APIから取得し、補助GeoJSONとしてローカル同梱します。OSMの編集APIはアプリ実行時・今回の補助データ取得には利用しません。

## 全駅共通の地図処理

`StationMapBuilder(Station, hint, reveal)`のインターフェースを維持しています。全20駅は同じ`RealStationMap`、同じ`quizMapStyle`で表示し、中心だけをStationの座標から取得します。GameはMapLibreをimportしません。

| 状態 | Widget短辺の表示幅の目安 | 開示 | 得点 |
|---|---|---|---:|
| 初期 | 500m | 地物のみ、地図文字と正解ピンなし | 100 |
| ヒント1 | 1km | 地図文字なし | 70 |
| ヒント2 | 3km | 実線路に沿った路線名 | 40 |
| ヒント3 | 5km | 路線名＋実施設と地名 | 10 |

Web Mercator、緯度、Widget短辺の論理pxからズームを計算します。北向き、bearing/tilt=0、中心を常に指定し、650msのカメラアニメーションで広げます。nativeの移動・ズーム・ダブルタップ・回転・傾斜を全て無効化し、FlutterでもIgnorePointerで遮断します。出典UIは操作できます。正解位置と駅名は回答後にだけ別のFlutterオーバーレイで出します。

### 実線路とヒントラベル

ベクトルタイルには必要な路線名が揃っていないため、OSMで名前の付いた実線路wayを補助データにします。位置から路線名を推測しません。OSMの実頂点を保持し、同名wayをつなぐ場合も端点が一致する場合だけです。元way IDと元名称をpropertiesに残します。運営会社の接頭辞や付加的な橋名などは表示用名称から整理します。路線色は識別用で公式色を保証しません。

抽出時に駅から8km以内の頂点を持つ線路を選び、wayの全形状を保持します。既存10駅の入力は東京・横浜・名古屋・大阪・京都周辺の地域スナップショット、新規10駅は各駅中心の8km/4kmクエリです。元クエリの矩形範囲を`_provenance.sources`に記録しています。8kmは選択条件であり、元スナップショットが全方位8kmを完全にカバーするという保証ではありません。現在の500m〜5km表示の範囲を実描画で検証します。GeoJSONのbuffer=256でタイル境界に余白を設け、以前の近距離切り取りによる色付き線路の途切れを防ぎます。

貨物を含む路線名、貨物専用、側線・操車場は補助ヒントから除外します。元の地形としての線路は実タイルに収録される範囲で表示します。名前がない線路、未収録の路線・施設は架空の名前で補いません。

施設のラベル位置は実ノード、またはOSMポリゴンの境界中心です。正式な入口位置や最適な地図ラベル位置とは限りません。地名、公園、博物館等を共通条件で抽出します。施設18件・地名18件まで選び、重要施設を優先、同名の近接地物をまとめて過密表示を避けます。名称と位置の出典は元OSM要素IDで追跡できます。国立博物館・公園などの全館・全敷地を独自に描き足していません。

### 答えの漏出防止

通常の地図ラベルは一切使用しません。自前GeoJSONの名称だけを描画します。

1. 正解駅の名前、読み、別表記を正規化し、それを含むラベルを原則除外します。
2. 駅そのものや「駅前」「ステーション」「Station」「Stn」等の直接的な参照は常に除外します。
3. 市名を含む「名古屋城」「京都タワー」など有用な実ランドマークだけをStationの`allowedLabels`で明示的に許可します。OSMに収録された実地物にしか適用しません。
4. 個別に漏出する表現は`blockedLabels`で除外でき、許可設定より除外が優先します。
5. 路線名は従来どおり保守的に駅名を含むものを除外します。例えば新宿出題の西武新宿線、池袋出題の西武池袋線、大阪出題の大阪環状線は注釈対象から外れます。これらの線路形状自体は実タイルから表示します。

全ラベルの意味・略称・愛称を機械判定できる保証はありません。駅追加時に3段階ヒントを目視し、必要な名称例外だけをJSONで調整してください。

## 読み込み・通信エラー

TileJSONは8秒、描画待ちは25秒の上限。読み込み中は回答とヒントを無効化します。native idleだけでなく、実際に描画された道路・線路、近景では建物、ヒント2では路線名、ヒント3では施設/地名を確認します。失敗時は再試行を表示し、問題・点数・ヒントは維持します。実地図取得失敗を模式地図へ置き換えません。

SDKは個別の全タイル取得エラーをDartへ通知しないため、一部タイルの欠落を完全に検出する処理は未実装です。フォントやラベルの不足も描画確認・タイムアウトで扱います。低速回線で時間が足りない場合は再試行が必要です。

## 100駅へ増やす方法

- JSONの1件追加で出題対象になります。有効駅から常に10駅を無作為抽出し、同一ゲーム内の重複はありません。
- StationCatalogがID・必須項目・型・空欄・座標範囲・同一OSMノード・同位置/近接した同読み駅の重複を検証します。エラーには行番号相当の件数とIDを表示し、無効データでゲームを開始しません。
- `StationCatalog.select(region:, prefecture:, difficulty:)`で抽出できます。駅の地域・数値難易度で絞り込むUIは未実装です。ホームのEasy / Hard選択は選択肢の生成方法だけを変更し、両モードの出題対象・実地図・ヒント・採点は共通です。
- 新駅の地図処理やヒント処理は同じです。デバッグ版では未同梱の補助ヒントを共通OSM読取処理で取得します。ネットワーク失敗時は再試行となります。リリース版ではこの取得を無効化しています。
- 公開版は`python3 tool/prepare_station_maps.py --fetch --station <id>`で補助データを同梱してからビルドします。個別のDartコードは不要です。地域スナップショットからの一括生成も可能です。データ追加手順はREADMEを参照してください。
- ツールは不完全なOSM応答や欠落を検出し、既存アセットを不完全なデータで上書きしません。通信エラー後は30秒間隔で再試行します。

## Phase 2で変更した処理

- `assets/data/stations.json`に指定10駅を追加。全20駅を有効にし、名前・読み・都道府県・地方・暫定難易度1・座標出典ID・別名を登録。路線のメタデータも取得したOSM実線路から選びました。
- 新駅の補助GeoJSONを同梱。`allowedLabels`で博多区など安全な地名・都市ランドマークを許可し、札幌の「サツエキ」等の略称と明示的な閉館施設を除外しました。未収録の名称・形状は生成していません。
- 駅名除外の正規化を修正。回答用の末尾「駅」除去をラベル除外に流用していたため、`blockedLabels: ["札駅"]`が「札」へ短縮されて札沼線も隠していました。ラベルの末尾は保持し、データ生成側とDartの判定を揃えました。
- 共通スタイルの地名ラベルに上下左右の自動配置候補を追加し、余白を縮めて長い町名の折り返し幅を調整。施設と地名の衝突で、京都・仙台の地名が全て隠れるケースを検出したためです。地物の実座標と施設マーカーの位置は変更していません。
- データ準備ツールの`--station`を繰り返し指定できるようにし、複数新駅をまとめて更新。既存の補助データと出典も保持します。
- 検証コードだけで20駅を2ゲームに分け、全駅の4段階を確実に通過させます。本番は引き続きランダムに10問を選びます。地図の実描画件数・名称・待ち時間をJSONへ保存します。

既存の`lib/game/game.dart`・`lib/screens/app_screen.dart`・`lib/map/station_map.dart`・パッケージ構成は変更不要でした。駅別Widgetや駅別カメラ処理は追加していません。ホームの「20駅すべて実地図」は既存の件数表示が自動更新します。

追加：`docs/station-coordinate-sources.json`、`test/phase2_test.dart`、`integration_test/support/question_order_random.dart`。変更：駅/ヒントJSON、共通スタイル、準備ツール2ファイル、既存カタログ/地図テスト、統合テスト/ドライバー、READMEと本文書。

新駅の座標は`railway=station`のOSM元ノードから確認し、タグ・座標・取得クエリ・版を[座標出典データ](station-coordinate-sources.json)へ保存しました。大宮は埼玉県のJR、高松は香川県、仙台・新大阪は地下鉄以外、三ノ宮はJRの正式表記を選択しています。新幹線と在来線の全ホームの重心ではありません。

## 50駅・100駅へ拡張する際の課題

1. データの追加は共通ツールでまとめられますが、代表座標・同名駅の区別・正式名・略称の確認は必要です。公開版は補助データを事前同梱し、公開Overpassをアプリのバックエンドにしない運用を継続してください。
2. 20駅の地図は共通Widget・共通ヒント・共通ラベル判定です。駅固有のコードはありません。例外はJSONの除外/許可名称だけです。略称・愛称・間接的な施設名からの漏出は、人のレビューも必要です。
3. データは約5.2MBの一括JSONです。都市近接駅の同じ線路を重複同梱しており、100駅では地域別の共有データと必要な地域だけの読み込みを検討します。文字列とデコード後のオブジェクトが重なり、ファイル容量以上のメモリを使います。
4. 公開タイルのLOD・OSMの収録量・文字衝突により、駅ごとのヒント量が異なります。路線の別称、同じ路線の複数表記、営業路線と線路名の対応は元データの問題もあります。route relationやofficial_nameなどの実属性を使った整理が次の課題です。
5. 初期構造が似た直線上の駅は、線路名だけでは地域を絞り切れないことがあります。今回は難易度を一律1の暫定値とし、利用者の正答率・必要ヒント数は測定していません。難易度の極端な差を解消したとは言えません。
6. 新駅は指示書の地方名を採用し、既存データを保持しました。関西/近畿、中部・北陸/中部の分類が混在します。地域別モードの導入前に、地域コードと表示名の統一が必要です。
7. OpenFreeMapはAPIキーなし・無料・商用可・リクエスト数の上限なしという案内です。駅数での課金はありませんが、SLAはなくサービス変更・停止の可能性があります。出典とODbLデータの提供方法を公開前に確認してください。
